# 미리자리 — 서비스 검토 및 설계

작성 기준일: 2026-11-14 (2026-11-16 갱신)

## 1. 서비스 이름

**미리자리** (영문 MiriJari) — "예매 전에 미리 정해 두는 내 자리".

| 후보 | 판단 |
|---|---|
| 마이시트 / 마이싯 | MySeat은 항공·예약 앱에서 이미 널리 쓰여 검색·상표 구분이 어렵다 |
| 내자리 | 뜻은 좋지만 일반 명사라 상표 등록과 검색 노출이 불리하다 |
| 딱자리 | 개인 맞춤이라는 뜻은 담기지만 '미리 정한다'는 사용 장면이 드러나지 않는다 |
| **미리자리** (확정) | 티켓팅 전에 자리를 미리 정해 둔다는 핵심 사용 장면이 이름에 들어 있고, '자리어때'와 구분된다 |

확정 전에 할 일: KIPRIS 상표 검색(제9·35·41·42류), 도메인(`mirijari.com`/`.kr`) 확인. 이 두 가지는 아직 확인하지 않았다.

## 2. 아이디어 검토 — 수정이 필요한 부분

| 원안 | 문제 | 수정안 (구현 반영) |
|---|---|---|
| 공연장의 **현재 남은 자리**를 보여주고 그중 추천 | 인터파크·멜론티켓·YES24·영화관 3사 모두 잔여석 공개 API가 없다. 크롤링은 예매처 약관 위반이고 차단·법적 분쟁 위험이 크다 | ① 예매율을 가정해 인기 좌석부터 지우는 시뮬레이션 ② 좌석을 눌러 직접 매진 표시 ③ 예매 화면 캡처를 올리면 AI가 남은 자리 인식(베타). 장기적으로는 예매처 제휴 |
| **AI가** 자리를 추천 | LLM이 좌석을 직접 고르면 매번 답이 달라지고 없는 좌석을 지어낸다 | 추천은 계산 엔진(시야각·눈높이·단차 수식)이 하고, LLM은 결과를 그 사람 말투에 맞게 설명하고 고민에 답한다. 키 없이도 추천이 동작한다 |
| **몸무게** 입력 | 추천에 필요한 건 체중이 아니라 '좌석 폭·다리 공간이 필요한가'이고, 민감한 질문이라 이탈을 부른다 | "넓은 좌석·다리 공간 필요" 선택 항목으로 대체 |
| **성별** 입력 | 좌석 적합도에 직접 영향이 없다 | 선택 항목으로 두고 엔진에는 반영하지 않는다 (향후 통계용) |
| **오른손잡이 → 화면 좌측** | 근거가 확인되지 않은 가설이다 | 가중치 2%로 아주 약하게만 반영하고 결과에 "영향은 작게 반영"이라고 밝힌다. 사용자 피드백이 쌓이면 검증해 키우거나 뺀다 |
| 콘서트 좌석 지정 추천 | 콘서트는 공연마다 무대·구역 배치가 달라 좌석 번호 단위 데이터를 미리 가질 수 없다 | 구역 유형(플로어 앞/중/뒤, 1층 사이드/정면, 2층) 단위로 추천하고, 구역 안에서는 "몇 열·통로 쪽인지"를 조언 |
| 영화 상영관 선택 | 지점·상영관별 좌석 배치 DB가 공개돼 있지 않다 | 상영관 타입(일반/IMAX/돌비/4DX/ScreenX/리클라이너) + 행·열 수 입력. 대표 특별관은 프리셋, 정확한 배치는 캡처 인식 |
| 공연 목록을 조사해 업데이트 | 사람이 조사하면 유지가 안 된다 | KOPIS(공연)·KOBIS(영화) 공공 API를 매일 자동 수집 |

## 3. 추가로 알아야 할 것

- **API 키 발급 (무료, 본인 계정 필요)**: KOPIS, KOBIS. 둘 다 출처 표시 의무가 있어 화면에 표기해 두었다. KOPIS는 등록된 공연만 나오므로 일부 콘서트는 빠질 수 있다.
- **좌석 데이터의 정확도**: 현재 공연장 좌석도는 공개된 좌석 규모에 맞춘 근사 모델이다. 열·번호가 실제와 다를 수 있어 화면에 고지한다. 실측 데이터는 공연장 공식 배치도를 보고 직접 제작하거나 사용자 제보로 채워야 한다 (타사 좌석도 이미지를 그대로 쓰면 저작권 문제).
- **구단 홈구장·응원석 방향**: 시즌마다 바뀐다. 2026년 11월 기준으로 넣었고 확인하지 못한 항목(대전 한화생명볼파크 홈 응원석 방향, 창원체육관 공사 일정, V리그 신생 구단 홈구장)은 데이터에 안내 문구를 달았다. 시즌 개막 때마다 점검이 필요하다.
- **개인정보**: 지금은 서버에 아무것도 저장하지 않는다(기기 localStorage). 계정·서버 저장을 붙이는 순간 개인정보 처리방침, 수집 동의, 만 14세 미만 처리가 필요하다.
- **AI 기능은 보류 (2026-11-16 결정)**: `ANTHROPIC_API_KEY`는 광고 수입이 생긴 뒤에 넣는다. 그때까지 AI 코멘트와 캡처 인식은 꺼져 있고, 추천 엔진·지도·목록은 영향 없이 동작한다. 코드는 그대로 두므로 키만 넣으면 켜진다.
- **AI 비용**: 코멘트는 버튼을 눌렀을 때만 호출하고 IP당 분당 횟수를 제한한다. 기본 모델은 `claude-opus-5-5`, `ANTHROPIC_MODEL`로 `claude-haiku-5-5` 등으로 바꿀 수 있다.
- **수익 모델 후보**: 광고, 예매처 제휴 링크, 공연장·구단 제휴. 취소표 자동 알림·자동 예매는 예매처 정책과 충돌하므로 하지 않는다.

## 4. 설문 설계 (1분 이내, 전부 탭 선택)

| 묶음 | 항목 | 쓰임 |

## 5. 추천 엔진

모든 계산은 브라우저에서 돈다 (`src/lib/engine`). 서버가 없어도 된다.

**좌석 격자형 (영화관·극장)** — 좌석마다 물리 좌표(거리·좌우·높이)를 만들고 10개 요소를 0~1로 채점한다.

- 시야: 영화는 스크린 수평 시야각(목표 42°를 취향·상영관 타입으로 이동), 공연은 무대 전체 조망 + 무대 바닥이 보이는 내려다보는 각도
- 가까움(공연), 좌우 중앙, 목 각도, 음향 기준점 거리, 앞사람 가림(열 단차 + 내 앉은 눈높이), 통로 접근, 다리 공간, 가성비(등급), 주 사용 손
- 프로필이 요소별 가중치를 정하고, 인원수만큼 붙은 좌석 블록 단위로 점수를 매긴다
- TOP 3는 서로 다른 선택지가 되도록 2순위는 다른 열(또는 층), 3순위는 앞의 둘과 겹치지 않는 위치에서 고른다
- 추천 이유는 "이 좌석이 평균 좌석보다 어떤 요소에서 얼마나 나은가"를 계산해 상위 3개를 문장으로 만든다. 가장 뒤처지는 요소는 아쉬운 점으로 보여준다

**구역형 (아레나·경기장)** — 구역마다 13개 속성(가까움, 조망, 열기, 편안함, 음향, 그늘, 동선, 가격, 가족, 먹거리, 단차, 경사, 경쟁)을 두고 같은 방식으로 채점한 뒤, 구역 안에서 몇 열·통로 쪽인지를 규칙으로 조언한다.

**세 가지 상황**

| 상황 | 동작 |
|---|---|
| 자리 여유 | 전체 좌석에서 추천. 열별 점수 막대로 "한 줄 앞 vs 뒤" 비교 |
| 남은 자리 중 | 매진 좌석·구역을 뺀 뒤 추천 |
| 티켓팅 전략 | 누구나 노리는 초인기 좌석은 실패 확률만큼 감점하고, 2·3순위는 경쟁이 더 낮은 자리로 잡아 클릭 순서를 제시 |

경쟁 예상치는 지금은 "평균적인 관객이 좋아할 자리" 순위로 추정한 값이다 (§7 참고).

## 6. 시스템 구조

```
[브라우저]  설문 → 대상 선택 → 결과
   ├─ 추천 엔진 (순수 함수, 클라이언트에서 실행)
   ├─ 공연장·경기장 데이터 (코드에 포함)
   └─ public/data/*.json  ← 공연·영화 스냅샷

[빌드 시]  scripts/fetch-data.mjs → KOPIS·KOBIS 호출 → 스냅샷 생성
           GitHub Actions가 매일 05:00 KST에 재빌드해 갱신

[서버 (선택, Vercel)]  /api/explain        AI 코멘트·고민 상담
                       /api/parse-seatmap  예매 화면 캡처 → 좌석 배치·잔여석
```

- 스택: Next.js 16 (App Router) + TypeScript, 별도 UI 프레임워크 없이 CSS 변수 기반 스타일
- 배포: GitHub Pages(정적, 무료) 기본. AI 기능까지 쓰려면 같은 저장소를 Vercel에 연결
- 키는 서버·빌드 환경에만 두고 브라우저로 내려가지 않는다

### 좌석 단위 추천과 남은 자리 (2026-11-17 추가)

- **모든 추천은 몇 열·몇 칸까지**: 좌석 격자형은 "G열 8~9번", 구역형은 구역 안 대표 블록을 좌석 단위로 채점해 "13열 · 통로에서 3~4번째 칸"으로 안내한다. 실제 블록마다 열·좌석 수가 달라 좌석 번호 대신 통로 기준 위치로 표현한다.
- **구역 좌석표**: 구역을 누르면 예매 사이트의 블록 화면처럼 통로와 통로 사이 좌석표를 보여 준다.
- **남은 자리**: 예매처의 실시간 잔여석은 가져오지 않는다. 공개 API가 없고, 예매 사이트를 자동으로 긁어 오는 것은 약관 위반이자 차단·법적 분쟁 위험이 있기 때문이다. 대신 예매율 가정 + 좌석 직접 표시로 사용자가 실제 화면과 맞춘다. 실시간 연동은 예매처 제휴로만 가능하다.
- **광고**: 홈·목록·결과 세 곳에 영역을 두고, AdSense ID가 설정됐을 때만 표시한다.

## 7. 로드맵

1. **지금 (MVP)**: 4개 카테고리 추천, 3가지 상황, 좌석·구역 지도, 열별 비교
2. **데이터 정확도**: 인기 공연장부터 실측 좌석도 제작, "실제로 앉아 보니 어땠나요" 피드백 수집 → 가중치 보정
3. **좌석 경쟁률 (수시 원서 경쟁률 방식)**: 사용자가 "이 자리로 정했어요"를 누르면 공연·구역별로 집계해 실시간 선호도를 보여준다
   - 필요: DB(예: Supabase/Postgres), 익명 기기 ID, 공연 회차 단위 집계
   - 주의: 표본이 적을 때는 숨긴다(최소 표본), 한 기기 중복 집계 방지, 공개된 경쟁률이 쏠림을 더 키우지 않도록 "경쟁 낮은 대안"을 함께 제시
   - 지금의 사전 추정 경쟁치를 실제 집계로 교체하면 티켓팅 전략의 정확도가 올라간다
4. **광고 → AI 기능 켜기**: 광고 수입이 생기면 Vercel에 `ANTHROPIC_API_KEY`를 넣어 AI 코멘트·캡처 인식을 켠다
5. **제휴**: 예매처·구단과 잔여석 데이터 연동
